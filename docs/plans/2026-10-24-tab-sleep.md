# Tab sleep implementation plan

Steps use checkbox (`- [ ]`) syntax for tracking. Work through the tasks in order.

**Goal:** Brow uses as little memory as possible. Tabs you haven't looked at for a while unload their page and wake exactly where they were, and a low-memory warning from macOS puts every background tab to sleep at once.

**Architecture:**
- **Snapshots:** the engine can capture a page as a `TabSnapshot` (address, title and WebKit's opaque session state, which holds back/forward history and scroll position) and make a new tab from one.
- **The policy:** `BrowserWindowModel` decides which live tabs may sleep, swaps them for snapshots, and wakes them from the snapshot when they're selected again.
- **Scheduling:** a small `TabSleepSettings` type in `Browsing` holds the user's choice. The app runs the timer and listens for memory pressure.
- **Measurement:** a script measures Brow's total memory before and after, against a fixed set of pages, in a throwaway data folder.

**Tech stack:** Swift 6 language mode, SwiftPM, Swift Testing, AppKit, WebKit (only in `WebKitEngine`), Dispatch memory pressure sources.

**Spec:** `docs/design/2026-10-23-brow-design.md`, trait 5 ("The feel"), plus the owner's request on 2026-10-24 that Brow use as few resources as possible. That request isn't in the design yet, so Task 4 adds it to Decisions.

## Global constraints

- Everything from the earlier plans still applies:
  - macOS 15 floor, tools version 6.0.
  - No AI tool mentions anywhere in the repository. Plain imperative commit subjects with no attribution lines.
  - No telemetry.
  - No WebKit import outside `WebKitEngine`.
  - Every `xcodebuild` command uses `-skipPackagePluginValidation`.
- Tabs sleep after 15 minutes without being shown, by default.
  - The choices are 5 minutes, 15 minutes, 1 hour and Never.
  - The choice is stored in `UserDefaults` key `SleepTabsAfterMinutes`, where 0 means never.
- These tabs never sleep:
  - a window's selected tab, and every pane of its selected split
  - the Peek page, which isn't in `liveTabs` anyway
  - pages playing media (`WKMediaPlaybackState.playing`)
  - pages using the camera or microphone
  - pages with a JavaScript dialog waiting for an answer
- A sleeping tab keeps its sidebar row, title and icon. It wakes where it was: same address, back/forward history and scroll position. A pinned tab that navigated away wakes on the page it was showing, not its saved address.
- A memory warning from macOS (`.warning` or `.critical`) sleeps every tab that may sleep, whatever its age.
- The sleep timer checks once a minute.

## Review focus

1. **Music or a video in a background tab.** It keeps playing and never sleeps. (Task 2)
2. **A video call in a background tab** (camera or microphone on). It never sleeps. (Task 2)
3. **Waking a pinned tab that had moved on.** It wakes on the page it was showing, with Back working, not on its saved address. (Tasks 1 and 2)
4. **A memory warning while you're in a split or Peek.** The selected tab, every visible pane and the Peek page stay loaded. (Task 2)
5. **A background page waiting on an `alert()` or `confirm()`.** It doesn't sleep, so the page doesn't lose the answer it's waiting for. (Task 2)

### Task 2: Sleeping and waking tabs

**Files:**
- Modify: `app/Packages/Sources/Browsing/BrowserWindowModel.swift`
- Test: `app/Packages/Tests/BrowsingTests/BrowserWindowSleepTests.swift`

**Interfaces:**
- Consumes: Task 1's `snapshot()`, `isPlayingMedia()`, `isUsingCameraOrMicrophone` and `makeTab(restoring:)`.
- Produces on `BrowserWindowModel`:
  - `@discardableResult public func sleepTabs(unusedFor interval: TimeInterval) async -> [ItemID]`. It puts to sleep every live tab that may sleep and was last active at least `interval` ago, then returns them. `lastActiveAt` comes from the sidebar's tab info, falling back to the item's `createdAt`. An interval of 0 is used for memory pressure.
  - `public func isSleeping(_ id: ItemID) -> Bool`
  - Selecting a sleeping tab wakes it from its snapshot. That includes waking it as a split pane through `setSelection`.

- [ ] **Step 1: Write the failing tests**

Use the clock harness from `BrowserWindowSplitTests.swift`, whose clock advances 1 second per read and can jump.

  - Expect:

    - `u2` stays live
- `recentTabsStayAwake`
  - Do: same, but advance only 5 minutes.
  - Expect: an empty result.
- `wakingRestoresTheSnapshot`
  - Do: select `p1`, call `live("p1")!.load(other)`, select `u1`, advance the clock and sleep `p1`, then select `p1`.
  - Expect:

    - `live("p1")?.loadedURLs.first == other`
    - `!isSleeping("p1")`
- `playingTabsNeverSleep`
  - Do: set `u1`'s `isPlayingMediaForTesting = true`, then advance and sleep.
  - Expect: `u1` stays live.

- [ ] **Step 2: Run them and see them fail**

- [ ] **Step 3: Implement**

- **Storage:** keep `snapshots: [ItemID: TabSnapshot]` beside `liveTabs`. It's `@ObservationIgnored`, except for `isSleeping`, which the sidebar reads.
- **Sleeping a tab:** take the snapshot, then go through the existing `unload(_:)` so dialogs, delegates and closing stay in one place.
- **Waking:** `register` the restored tab. The opener links stay as they are.
- **Cleanup:** `close`, `clearUnpinned`, `reconcile` and `closeAllLiveTabs` drop snapshots for items they remove or unload.
- **Media check:** ask each candidate's `isPlayingMedia()` one at a time. After each `await`, check again that the tab is still live and still may sleep. The selection may have changed in the meantime.

### Task 3: Sleep settings

**Files:**
- Create: `app/Packages/Sources/Browsing/TabSleepSettings.swift`
- Test: `app/Packages/Tests/BrowsingTests/TabSleepSettingsTests.swift`

**Interfaces:**
- Produces: `public struct TabSleepSettings`:
  - `public static let choices = [5, 15, 60, 0]`, in minutes, where 0 means never
  - `public static let key = "SleepTabsAfterMinutes"`
  - `public init(defaults: UserDefaults = .standard)`
  - `public var minutes: Int`. It reads the stored value, falls back to 15, and treats a stored value outside `choices` as 15. Setting it stores the value.
  - `public var interval: TimeInterval?`. It's nil for never, otherwise `minutes * 60`.
  - A launch argument `-SleepTabsAfterSeconds <n>` overrides `interval` for measurement runs, because `UserDefaults` reads the argument domain first. The getter checks that key before `SleepTabsAfterMinutes`.

- [ ] **Step 1: Write the failing tests**

Each test uses a fresh `UserDefaults(suiteName:)`.
- `defaultsToFifteenMinutes`: expects `minutes == 15` and `interval == 900`.
- `neverMeansNoInterval`: after setting `minutes = 0`, expects `interval == nil`.
- `unknownValuesFallBack`: after storing 7 directly, expects `minutes == 15`.
- `secondsOverrideWins`: after setting `SleepTabsAfterSeconds` to 30 on the suite, expects `interval == 30`.

- [ ] **Step 2: Run them, see them fail, implement, see them pass, commit**

### Task 4: The app: timer, memory pressure, menu and measuring

**Files:**
- Create: `app/Brow/TabSleeper.swift`, `scripts/measure-memory.sh`, `scripts/measure-pages.txt`
- Modify: `app/Brow/AppDelegate.swift`, `app/Brow/MainMenu.swift`, `README.md`, `docs/design/2026-10-23-brow-design.md` (Decisions)

**Interfaces:**
- Consumes: Tasks 2 and 3.

- [ ] **Step 1: Sleep on a timer and on memory pressure**

These pieces have no app-target tests.
- **`TabSleeper`** is created by `AppDelegate` with a closure that returns every window's model.
  - **Every 60 seconds:** when `TabSleepSettings().interval` isn't nil, it calls `sleepTabs(unusedFor:)` on each model.
  - **Memory warnings:** a `DispatchSource.makeMemoryPressureSource(eventMask: [.warning, .critical], queue: .main)` calls `sleepTabs(unusedFor: 0)` on each model.
- **Tab menu:** a "Sleep Unused Tabs After" submenu, built like "Archive Unpinned Tabs After". Its items are "5 Minutes", "15 Minutes", "1 Hour" and "Never", with a checkmark on the current choice.

- [ ] **Step 2: Show sleeping tabs as sleeping**

`SpacePageView` already greys the title of tabs with no live page. Sleeping tabs use the same `secondaryLabelColor`, so nothing new is needed beyond checking it by eye.

- [ ] **Step 3: A throwaway data folder for measuring**

- **The argument:** `AppDelegate` reads `UserDefaults.standard.string(forKey: "BrowDataFolder")`, set with the launch argument `-BrowDataFolder <path>`. When it's set:
  - the sidebar, archive, history, favicons and ad blocking files all live under that folder instead of `~/Library/Application Support/Brow`
  - `FirstRunImport` is skipped, so it starts with an empty sidebar
- **Opening pages:** a second argument, `-BrowOpenPages <file>`, opens each line of that file as a new tab, one every 4 seconds, in the first window.

- [ ] **Step 4: The measuring script**

`scripts/measure-memory.sh` does this in order:
1. Builds the Release configuration, ad hoc signed, into `.build/measure`.
2. Starts that app's binary directly with `-BrowDataFolder <tmp> -BrowOpenPages scripts/measure-pages.txt -SleepTabsAfterSeconds 60`.
3. Waits until every page has opened, plus 20 seconds, then prints the "loaded" total.
4. Waits a further 90 seconds and prints the "after sleep" total.
5. Quits the app and deletes the temporary folder.

Each total is Brow's own footprint plus every `com.apple.WebKit.*` process started after Brow launched, summed with `footprint`. The script says to quit Safari and Mail first, because their WebKit processes would be counted otherwise.

`scripts/measure-pages.txt` lists 10 public pages, one per line:
- `https://en.wikipedia.org/wiki/Web_browser`
- `https://github.com/DotDeon/brow`
- `https://www.bbc.com/news`
- `https://www.theverge.com`
- `https://www.apple.com/macbook-air/`
- `https://news.ycombinator.com`
- `https://www.reddit.com/r/macapps/`
- `https://developer.apple.com/documentation/webkit`
- `https://www.youtube.com`
- `https://www.nytimes.com`
