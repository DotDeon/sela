# Sidebar implementation plan

Steps use checkbox (`- [ ]`) syntax for tracking. Work through the tasks in order.

**Goal:** Replace the temporary tab list with Arc's sidebar: favourites grid, pinned tabs and folders, unpinned tabs, spaces you swipe between, drag and drop, a sidebar that hides and slides out, and everything saved between launches. On first launch Brow offers to import the owner's Arc sidebar.

**Architecture:** The sidebar document (from the foundation plan) becomes the source of truth for tabs. A shared `SidebarStore` owns it and saves it. Each window's `BrowserWindowModel` maps sidebar items to live engine tabs, which load lazily when an item is selected. Pure layout logic (outline rows, drop targets, animated updates, paging) lives in the `Sidebar` module with tests. The AppKit views live in a new `SidebarUI` module. A new `Favicons` module fetches and caches site icons.

**Tech stack:** Swift 6 language mode, SwiftPM, Swift Testing, AppKit (`NSOutlineView`, `NSCollectionView`, `NSScrollView`), Observation, WebKit (engine only). No third-party dependencies.

**Spec:** `docs/design/2026-10-23-brow-design.md`, sections "What makes Arc's sidebar different" (all five traits), "Sidebar data model", "Import from Arc" (sidebar part only), milestone 3, and step 4 of "Order before the new Mac arrives".

**Next plans:** archiving (unpinned tabs closing themselves after 12 hours), command bar, split view and Peek. Then sync.

## Global constraints

- Everything from the earlier plans still applies: macOS 15 floor, tools version 6.0, no AI tool mentions anywhere in the repository, plain imperative commit subjects with no attribution lines, no Arc assets, no telemetry, no WebKit import outside `WebKitEngine`.
- No Arc code, icons or artwork. Arc's space icon names (for example `planet`) are shown with the SF Symbol of the same name when one exists, otherwise as text.
- The sidebar file stays at `~/Library/Application Support/Brow/Sidebar.json`. Favicons are cached in `~/Library/Application Support/Brow/Favicons/`.
- Favicons come only from the site itself (`<link rel="icon">` or `/favicon.ico`). No third-party favicon services, since they'd see every site the user has.
- Keyboard shortcuts follow Arc: Cmd+S toggles the sidebar, Cmd+D pins or unpins, Cmd+Option+N makes a folder, Cmd+Shift+C copies the URL, Ctrl+1 to Ctrl+9 pick a space, Cmd+Option+Left and Right move between spaces, Cmd+1 to Cmd+9 pick a tab (favourites first, 9 is last).
- New tabs go to the top of the current space's unpinned section, under "+ New Tab", as in Arc.

## Review focus

1. **Two windows on one sidebar.** Closing an unpinned tab in one window removes it from the sidebar, so the other window must drop its live copy instead of keeping a page for an item that no longer exists. (Task 5)
2. **Quitting right after a change.** Saving waits 0.5 seconds to batch changes. Quitting inside that window must still save. (Tasks 2 and 8)
3. **A sidebar file from a newer Brow.** Brow must never overwrite it, even after edits, because that would destroy the newer data. (Task 2)
4. **Impossible drops.** Dropping a folder into its own subfolder, onto a tab, or onto the divider is refused without changing anything. (Tasks 1 and 6)
5. **Deleting spaces.** Deleting the space you're looking at moves the window to another space. The last space can't be deleted. (Tasks 1 and 5)

Rules the tests pin:

- **Opened pages.** A page that opens a tab (popup, `target=_blank`, Cmd-click) creates an unpinned item in the current space. When the opener is unpinned, the new item goes after it and after the run of items it already opened. Otherwise it goes at the top of unpinned, after that run. The plan 2 rules carry over: opener links, siblings first, and forgetting links on an unrelated selection.
- **Closing the selected item.** The next selection is the next sibling with the same opener, then the opener, then the item below in tab order, then the item above, then nothing.
- **Page changes.** `tabStateDidChange` calls `sidebar.recordPage`.
- **Selection changes** call `sidebar.markActive` for the item being left and the item being selected.

**Files:**

**Interfaces:**
- Produces, in `Sidebar`:
  - `enum OutlineRow: Hashable, Sendable { case item(ItemID), divider }`
  - `func rootRows(for space: Space, in document: SidebarDocument) -> [OutlineRow]` gives pinned children, then `.divider`, then unpinned children.
  - `func childRows(of id: ItemID, in document: SidebarDocument) -> [OutlineRow]`
  - `typealias OutlineSnapshot = [OutlineRow?: [OutlineRow]]`, keyed by parent with nil for the root. Folders appear only when expanded.
  - `func outlineSnapshot(for space: Space, in document: SidebarDocument) -> OutlineSnapshot`
  - `enum OutlineUpdate: Equatable { case remove(parent: OutlineRow?, index: Int), insert(parent: OutlineRow?, index: Int) }`
  - `func outlineUpdates(from old: OutlineSnapshot, to new: OutlineSnapshot) -> [OutlineUpdate]`
  - `func dropDestination(parent: OutlineRow?, childIndex: Int, space: Space, document: SidebarDocument) -> (parent: ItemID, index: Int?)?`
  - `func targetPage(startPage: Int, offset: CGFloat, pageWidth: CGFloat, velocity: CGFloat, pageCount: Int) -> Int`
  - `let defaultSpaceColors: [RGBAColor]` and `func themeColor(for space: Space, at index: Int) -> RGBAColor`

Values:

- `defaultSpaceColors`, in order (red, green, blue in 0 to 1, alpha 1):
  1. blue (0.36, 0.55, 0.93)
  2. purple (0.60, 0.45, 0.90)
  3. pink (0.93, 0.45, 0.66)
  4. red (0.90, 0.38, 0.35)
  5. orange (0.96, 0.60, 0.30)
  6. yellow (0.93, 0.78, 0.30)
  7. green (0.40, 0.75, 0.45)
  8. grey (0.55, 0.57, 0.60)
- `themeColor` uses the space's theme. With no theme it uses `defaultSpaceColors[index % 8]`.
- `targetPage`:
  - Positive velocity means moving towards later spaces.
  - When `abs(velocity) >= 200` points per second, the result is `startPage ± 1` in the direction of the velocity.
  - Otherwise it's `round(offset / pageWidth)`.
  - The result is clamped to `0..<pageCount`, and a swipe never moves more than one page.
- `dropDestination`:
  - At the root, an index up to the pinned count goes to the pinned section at that index. An index after the divider goes to unpinned at `index - pinnedCount - 1`.
  - On a folder with index -1, the item goes at the end of that folder. On a folder with index n, it goes at n in that folder.
  - On a tab, on the divider, or at the root with index -1, the result is nil.
- `outlineUpdates` only compares parents present in both snapshots. It uses `CollectionDifference`. All removals come first, in descending index order per parent, then all insertions in ascending order. A moved row becomes a remove and an insert.
